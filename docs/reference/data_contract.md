# Контракт одной новости

Любой адаптер источника возвращает одинаковую запись с шестью полями.
Дополнительные сведения можно положить в необязательный metadata.
Корпус храним в JSONL UTF-8: одна запись на строку.

```json
{
  "id": "web:example.org/news/123",
  "text": "Исходный текст новости",
  "url": "https://example.org/news/123",
  "source": "example.org",
  "published_at": null,
  "language": "ru"
}
```

| Поле | Значение |
| --- | --- |
| id | Устойчивый ключ публикации; не зависит от имени файла и номера строки |
| text | Непустой исходный текст |
| url | Ссылка на публикацию или null, если ссылки нет |
| source | Источник: домен сайта, ID канала или название сценарного набора |
| published_at | Известное время публикации с часовым поясом или null |
| language | Язык текста или null |
| metadata | Необязательный объект с остальными исходными полями |

Для веб-новостей id получаем из URL; для Telegram — из channel_id и message_id.
Повторное чтение той же публикации должно давать тот же id.
Неизвестные сведения оставляем null и не восстанавливаем догадками.

## Текущая выгрузка

Используем локальный XLSX `data/raw/trade_news/relevant_trade_news_202606112005.xlsx`.
Его путь и SHA256 сохранены в [манифесте](trade_news_full.json).

- text берём из `text`, url — из `url`, source — из домена ссылки, language — из `orig_lang`.
- published_at в исходном JSONL равен null. Календарный день используем при индексации.
- Исходный UUID, `dates`, заголовки, переводы и метки сохраняем в metadata.
- Заголовки и резюме не подменяют исходный text и не становятся эталонами.
- Пустые тексты, полные дубли строк, неоднозначные версии ID/URL и тексты на пределе Excel
  уже исключены из рабочего XLSX; правила и числа сохранены в отчёте EDA и манифесте.

## Нормализованный корпус

Готовый файл — data/processed/trade_news/news.jsonl, UTF-8, одна новость на строку.
Преобразование выполняет `scripts/import_trade_news.py`.
[Команда запуска с локальной копией манифеста](../../README.md#преобразование-xlsx).

Для этого адаптера URL технически приводится к ASCII URI: домен — к IDNA,
кириллица, пробелы и незакодированный процент — к процентному кодированию.
Схема и домен приводятся к нижнему регистру. Параметры запроса, фрагмент
и готовые escape-последовательности сохраняются.
id равен префиксу web: и SHA256 полученного URI в UTF-8.
Повторные строки одного URI с одинаковым text объединяются в одну новость.
Разные тексты одного URL приводят к ошибке импорта, без выбора произвольной версии.

Все 15 исходных колонок, кроме text, сохраняются без преобразования
в списке metadata.records. В том числе metadata.records[].id — исходный UUID,
а не ID нормализованной новости. Исходный URL находится в records[].url.
По text и каждому элементу records можно
восстановить все 16 значений соответствующей исходной строки.

language берётся из единственной известной метки orig_lang для данного URL.
Если метки отсутствуют или противоречат друг другу, language равен null;
исходные значения остаются в records.

Импортёр добавляет в metadata идентификатор набора dataset_id, SHA256 текста
content_sha256 и observed_at — время подтверждённого наблюдения текста при импорте.
При повторном импорте выгрузки с тем же SHA256 сохраняется время из манифеста.

На выборке публикаций 9–11 июня 2026 поле `dates` совпало с календарным
днём на страницах издателей. [Интерфакс, 9 июня](https://www.interfax.ru/business/1094998),
[ПортНьюс, 10 июня](https://portnews.ru/news/392737/),
[Коммерсантъ, 11 июня](https://www.kommersant.ru/doc/8736437).

Индекс использует самый поздний корректный день из значений `dates` одного URL.
Статья доступна с конца этого дня по Москве. При отсутствии корректной даты
действует время импорта.
Сверка выборочная. Для вопросов, где важна точная историческая дата, сверяем
дату и текст с первоисточником.
Имя файла, лист, строка и связь исходного UUID с ID новости находятся в журнале
logs/imports/trade_news_full.jsonl. Схема, хеши входа, результата и кода,
число объединённых строк и языки фиксируются в секции normalized манифеста.

Проверяются все записи по JSON Schema с проверкой форматов. После записи JSONL
перечитывается целиком: ID и URL должны быть уникальны, тексты и records —
совпадать с исходником. Сам XLSX при нормализации не изменяется.

## Подготовленный корпус Telegram

Выгрузка 12 каналов за скользящий год находится в
data/raw/telegram/all12_last12months_20251109.jsonl. Экспортёр уже возвращает
записи по этому контракту. scripts/import_telegram.py исключает только сообщения,
весь текст которых состоит из одного @username с необязательными пробелами.
Запуск из корня проекта:

    python -m scripts.import_telegram --manifest data/processed/telegram/manifest.json

Результат — data/processed/telegram/news.jsonl: 89 828 сообщений из 89 832 исходных.
Исключены четыре сообщения с текстом @meduzalive. Остальные строки, их порядок,
тексты и все metadata сохранены побайтово; одинаковые тексты разных публикаций
не объединяются. id имеет вид tg:<channel_id>:<message_id>, source — tg:<channel_id>.
published_at сохраняет дату Telegram, language остаётся null.
Исходное observed_at не заменяется временем импорта.

[Манифест](telegram_all12.json) содержит ID и номера строк
исключённых сообщений, количества по источникам, хеши исходника, результата,
схемы и импортёра. Все записи проверяются по JSON Schema с проверкой форматов;
результат перечитывается для точного сравнения с оставшимися исходными строками.
Сырой файл не изменяется. Существующие результаты не перезаписываются.
Это файловый корпус; загрузка в хранилище и индекс выполняется отдельно.

## Что делает конвейер

При импорте система сама рассчитывает хеши, фиксирует время наблюдения и хранит
версии при изменении текста. Имя файла и строка остаются в журнале импорта,
параметры обработки — в манифесте. Эти поля не нужны во входной записи новости.
Внутреннее хранение описано в [архитектуре](architecture.md).

После замены корпуса повторяем импорт и пересборку индекса. Основной код RAG
и API работают с теми же полями. Старые оценочные вопросы и доказательства
остаются привязаны к своему срезу корпуса.

Структура записи задана в [JSON Schema](../../schemas/news_document.schema.json).
Результаты проверки исходных файлов — в [едином отчёте EDA](../../eda/README.md).
